## Overall Impression

整ったカードだが、答えている問いがずれている。今のカードは「この投稿はどんな見た目か」に答えている。着く前に答えるべきは「そっちへ歩くべきか、着いたら何が待っているか」。最大の機会は、写真をごほうびとして取っておき、カードを「方角と距離」中心に組み直すこと。

## What's Working

- 円の中心は投稿 ID から決まる向き・距離でずらしていて、何度見ても同じ（postReveal.ts）。見比べて本当の地点を割り出せない、丁寧な作り。
- 着く前はお気に入りを出さない（登録すると正確な座標が残るため）。ズーム 13 未満はカードを隠して点とクラスタにする。散らかりの抑え方として妥当。
- ガラス調のトークン、角丸、44px のハートなど、アプリの他の部品と同じ見た目で揃っている。

## Priority Issues

**[P1] 写真が着く前から全部見えている**
- なぜ問題か: 着いたときのごほうびを先に渡してしまい、行く理由が弱くなる。景色（鉄塔・木・家並み）から場所の見当もつき、円をずらした意味が薄れる。
- 直し方: 着く前は写真を強くぼかす（色と光の雰囲気は残る）か、地平線の細い帯だけ見せる。着いたときにピントが合うように 0.6 秒ほどで鮮明にする。※画像の URL はクライアントに届いたまま（見せ方の対策）。
- コマンド: /impeccable shape（ぼかしか帯か決める）→ /impeccable delight（ピントが合う瞬間）

**[P1] 載せている情報と順番が「行くか決める」に合っていない**
- なぜ問題か: 一番大事な「どっちに・どれだけ」が 11px の白 60% で、地域名と同じ行。方角はない。キャプションが一番目立っている。
- 直し方: 上から「方角＋距離のチップ（例: 北東 1.2km、端末の向きで回る小さな矢印）」→ キャプション → 「日野市 付近 · 投稿日」。解放の条件は「100m で解放」の短い印にして、カードが出ているズームでは常に出す。
- コマンド: /impeccable clarify → /impeccable layout

**[P1] カードが手がかりの円を隠している**
- なぜ問題か: カードは円の中心から 12px 上に付いているので、z14.5 では円の上半分、z15 以上では円の約 3 割を覆う（実測 248×214px）。探しに寄った瞬間に手がかりが見えなくなる。
- 直し方: カードを円の上端の外に出す（半径ぶん上にずらす）。または z13〜14 は小さなピル（方角と距離だけ）にして、押したときだけカードを開く。
- コマンド: /impeccable layout → /impeccable adapt

**[P2] 状態ごとの見せ方がない**
- 現在地がない: 距離が黙って消える。「位置情報をオンにすると方角と距離がわかります」の印を出す。
- 地域名がない: Supabase の投稿には地域名がないため「この辺り 付近」になる（postsApi.ts の dbPostToPost が area を作らない）。「この近く」に変える。
- 近い（300m 以内）: 一番わくわくする場面なのに何も変わらない。「あと約 180m」に変え、円をやさしく脈打たせる。
- 写真がない: 文字だけに崩れる。夜空のグラデーションの代わりの絵を出す。
- コマンド: /impeccable harden

**[P2] 読みやすさとアクセシビリティ**
- 説明の行が 10px・白 50%。ポテンシャルの色の上では約 4.7:1 まで落ちる。最小 12px にする。
- カードに role も aria-label もなく、押せる要素が 0 個。スクリーンリーダーでは仕組みが伝わらない。カード全体を「円へ寄る」ボタンにし、「夜景の投稿、日野市付近、北東 1.2km」のような名前を付ける。
- カードが出るときの動き（night-popup-rise）は「動きを減らす」設定でも止まらない（index.css の reduced-motion の一覧に入っていない）。
- コマンド: /impeccable audit → /impeccable polish

## Persona Red Flags

- **Casey（片手でスマホ、気が散りがち）**: 夜道で一目見て「どっちへ歩けばいいか」が分からない。文字は 10〜13px。z13 以上ではカードが何枚も地図を覆い、右下のボタン列とも重なる（実測で 5 枚目のカードがボタン列の下に入っていた）。カードを押しても何も起きない。
- **Jordan（初めて使う人）**: 破線の円の意味も、100m で解放されることも、ズーム 15 未満では知る手段がない。位置情報を許可していないと距離が出ず、理由も出ない。「この辺り 付近」で首をかしげる。
- **Sam（スクリーンリーダー）**: 写真は alt=""、カードは名前のない div の集まりで、キーボードではたどり着けない。近づいたときの変化も読み上げられない。この仕組み自体を体験できない。

## Minor Observations

- 着いた後のカードには投稿者名があるが、着く前にはない。「〇〇さんが見つけた場所」は行く動機になりうる。
- img の width/height（232×131）が HTML に直書きで、CSS の 16:9 と二重管理。
- 破線の円（#c4b5fd、1.5px）は航空写真の上では見えにくくなる可能性がある。
- デモ投稿のキャプションが「夜の散歩にちょうどいい。」など一般的で、カードがテンプレートっぽく見える。
- 着いたときの「投稿の場所に着きました: 〇〇」は事実を伝えるだけで、ごほうびの演出になっていない。
- z13 以上で 10 枚近いカードがそれぞれ backdrop-filter を持つと、中位のスマホでは地図の動きが重くなる可能性がある（未計測）。

## Questions to Consider

- 写真がごほうびなら、なぜ先に無料で渡しているのか。ぼかした写真は「行きたい」を生み、鮮明な写真は「もう見たから行かなくていい」を生むのでは。
- コンパスのアプリなのに、投稿カードには方角がない。カードがまず「方角」で、次に「写真」だったら？
- 着く前の主役はカードではなく円なのでは。地図には破線の円だけがあり、押したときだけカードが開く画面はどう感じるか。
- あと 50m のところで、カードは 15km 先のときと同じでいいのか。少しずつ写真が鮮明になる、振動する、などの変化があったら？
