# Directional Field — Figma再現仕様

添付画像に対応するのは `field`（試作）です。実装の正本は `PrototypeCard.tsx`、`prototypes/DirectionalField.tsx`、`prototypes/canvas.ts`、`compassCanvas.ts`。この仕様は2026-10-02のソースから取得しています。

## カード

CSSのremを16pxとして換算。横幅は親に追従し、固定値ではありません。画像に近い再現例はカード幅272px、内部Canvas幅246pxです（左右padding 12px + border 1pxずつ）。この例のカード高さは314.5pxです（画像の実測値ではなくCSSからの計算値）。

|項目|Figma設定|
|---|---|
|フレーム|幅272px、縦Auto Layout、左右上下padding 12px、stroke 1pxを内側に配置|
|角丸|16px|
|塗り|#09090B / 90%|
|枠|#FFFFFF / 10%、1px|
|背景ぼかし|24px（CSS backdrop-blur-xl。Figmaとの視覚差は調整が必要）|
|影|X 0、Y 25、Blur 50、Spread -12、#000000 / 25%（Tailwind shadow-2xl。Figmaの影は同等値を起点に調整）|
|見出し領域|左右padding 4px、内部幅238px|
|タイトル|Directional Field、12px、Bold 700、行高16px、字間0.6px、#FFFFFF / 80%|
|説明|方向の強さ · 200 m以内、11px、Regular 400、行高16.5px、#FFFFFF / 40%|
|タイトル→説明|2px|
|説明→Canvas|8px|
|Canvas領域|246 × 246px、角丸12px、Clip content ON、#080B10|

カード左上を(0,0)とした位置：タイトル領域(17,13)、説明領域(17,31)、Canvas(13,55.5)。タイトルと説明は文字の可視輪郭ではなく行ボックスの座標です。添付画像の外側余白や背後の色はこのカードの一部ではありません。

Web本文のフォントは `-apple-system, BlinkMacSystemFont, Segoe UI, Roboto, …, sans-serif`。Canvas内の方位文字は `system-ui, sans-serif`。macOSで再現するときはSF Pro系を起点にします。実際のフォントはOS依存なので、特定のフォントファイルが指定されているわけではありません。

## 円と方位：Canvas内部の座標

実装は300 × 300の論理座標で描画し、CSSでCanvas幅に縮小します。Figmaが246pxの場合、係数 k = 246 / 300 = 0.82。下記はCanvas左上が原点です。

|---|---|---|
|中心|(150,150)|(123,123)|
|リング内半径|104|85.28|
|基礎リング外半径|114|93.48|
|基礎リング太さ|10|8.2|
|強度による外側拡張|0〜12|0〜9.84|
|最大外半径|126|103.32|

|E中心|(290,150)|(237.8,123)|
|S中心|(150,290)|(123,237.8)|
|W中心|(10,150)|(8.2,123)|
|方位文字|15px、600|12.3px、600|

基礎リングは白8%の塗り。Figmaでは中心(123,123)に直径186.96の円、stroke 8.2を**内側**に配置すれば内半径85.28・外半径93.48になります。中央のマーカー外輪のstrokeは中央配置です。

方位文字は横・縦とも中央揃え。Nは #F87171 / 95%、E/S/Wは #FFFFFF / 55%。CanvasのtextBaseline=middleとFigmaの文字ボックスは厳密には一致しないため、最終的な文字位置は目視調整します。

## 色と形が決まる仕組み

1. 選択地点の24方位（15°刻み）で、選択Range以内の最大ポテンシャル値を採用。200mなら距離0 / 25 / 50 / 100 / 200mが対象。中心値は全方位で共有されます。
2. 生値 raw が閾値0.006未満なら強度0。それ以外は `s = clamp((raw - 0.006) / (0.1635 - 0.006), 0, 1)^0.55`。
3. 24方位のsを円周上のガウス重み付き平均（σ=18°）で360方位へ補間。
4. 2°刻みの180セグメントを生成。各セグメントは開始方位aの `s[a+1]` を採用し、0.02以下は描画しません。
5. 内半径104、外半径 `114 + 12s`、開始a、終了 `a + 2.6°` の扇形を描画。隣接セグメントを0.6°重ね、隙間を防ぎます。

角度0°は上（北）、90°は右。座標式は `x=150+r*cos((a-90)π/180)`、`y=150+r*sin((a-90)π/180)`。端末方位または地図bearingに合わせて、円と方位文字を中心まわりに `-rotation` 度回転します。添付画像のようにNを上へ置く場合はrotation=0。

色は次の6色を**強度0〜1の等間隔**に配置し、隣接色のRGBを線形補間します。タイル用の生値のstop位置やRGBAのalphaは、この描画では使用しません。

|s|RGB|HEX|
|---|---|---|
|0|20,18,30|#14121E|
|0.2|38,25,74|#26194A|
|0.4|86,35,102|#562366|
|0.6|190,75,70|#BE4B46|
|0.8|255,166,0|#FFA600|
|1|255,239,120|#FFEF78|

主リングのopacityは `0.25 + 0.75s`。色と太さは各セグメントの強度に連動します。単純な円周グラデーションでは完全には再現できません。

発光はs≥0.35に追加：同じ扇形を色opacity 5%で描き、shadowColorは同色 / `8 + 32s` %、shadowBlurは `6 + 18s` px（300px座標）。Figmaでは発光用の扇形レイヤーを背面へ複製して調整します。Canvas shadowBlurとFigmaのLayer Blurはレンダリングが異なるため数値だけでは一致しません。

外周ハイライトはs≥0.5に追加：外半径上の円弧、stroke 1.5px、色は `color(min(1,s+0.15))`、opacity `60s` %。246px表示ではstroke 1.23pxです。

## Figmaで組む順番

1. 上記のカードをAuto Layoutで作成し、見出し・説明・正方形Canvasフレームを置く。
2. Canvas内に基礎リングを置く。
3. 発光用扇形、主リングの扇形、外周ハイライトの順で重ねる。円弧はFigmaのArcとInner radius、またはSVGの閉じたパスで作る。
4. 中心の外輪・白ドット、N/E/S/Wを置く。
5. カードは幅を変更可能にし、Canvas内部は一括Scaleする。300px座標で部品を作り、246pxへ縮小すると数値管理しやすい。

推奨レイヤー構成：Card / Header（Title, Subtitle）/ Canvas（Base ring, Glow, Field segments, Highlights, Center marker, Compass labels）。

## 完全一致に必要なデータ

添付画像からは、選択地点・当時のタイル・24方位の値が確定できません。色付き円弧の開始角・終了角・ピーク強度は固定のデザイン値ではなくデータ由来です。上記寸法は実装値ですが、画像の円弧を同じ形で生成するには、当時の `PotentialViewModel.directionProfile`（24要素のvisualStrength）とrotationが必要です。

実際の画面から取得する場合、React DevToolsで `DirectionalFieldView` のpropsにある `data.directionProfile` と `rotation` を確認します。directionProfileを上記smoothProfileと描画式に通し、SVGへ変換すればFigmaへベクターとして取り込めます。PNGスクリーンショットのみでは元データを厳密に逆算できません。

更新中だけCanvas領域全体がopacity 45%になり、中央に「更新中…」が重なります。添付画像は通常表示に見えるため、再現時はこの状態を無効にします。
