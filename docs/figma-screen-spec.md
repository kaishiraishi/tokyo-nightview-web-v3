# 現行画面（スマートフォン）— Figma 再現指示書

この資料は、2026-10-03 時点の実装（`main` の `601b604d`）から、**スマートフォンの画面**を Figma で組み直すための指示書です。寸法・色・文字・状態・デザインルールを、Tailwind のクラスと CSS、Canvas/SVG の描画コードから読み取っています。**コンパス関係（ミニコンパス・コンパスモード・地図上の距離リングとタップ地点・現在地の向き）は 4〜12 章で特に細かく書いています。** 組み終わったら、23 章「Figma でずれやすい点」で実画面との違いを確認してください。

- 対象: `src/App.tsx` → `src/components/potential/PotentialMapView.tsx` から表示される画面。画面幅 768px 未満（スマホ）のときの見た目。
- 対象外: PC の画面、旧画面（`MapViewExplore` / `MapViewAnalyze`、`TopBar`、`ScanControlPanel`、`ClassicPanels`、`PrototypePanel`、`CompassControl`、`CompassButton`）。
- 地図タイル・航空写真・投稿写真・表示モードのサムネイルは画像素材です。スクリーンショットを最下層に敷くか、無地のプレースホルダーにしてください（地図の層の値は 17 章）。
- 単位は CSS px（rem = 16px）。Tailwind v3 の既定値で換算しています。座標は **390 × 844 のフレームの左上が原点**、safe area（ノッチ・ホームバー）は 0 で計算しています。実機では `env(safe-area-inset-*)` の分だけ内側にずれます。
- 試作の全幅 Directional Field カード（今は画面にない）の詳細は [directional-field-figma.md](directional-field-figma.md)。

## 1. デザインルール

コードのコメントと `PROJECT.md`「Current UI」から読み取った決まりです。

### 1-1 基本方針

1. **地図が主役**。UI は地図の上に浮かべる部品として置き、画面を分割しない。探索モードには下部シートもない。面を持つのは、投稿モードの下部シートと、開いたときだけ出るカード・ダイアログ。
2. **データの意味が UI より先に伝わる**。ポテンシャルの色ランプは、地図・コンパス・凡例にだけ使う（UI の飾りにしない）。
3. **コンパスは「自分の位置から周りを感じ取る」道具**。目的地を示す矢印にはしない。方向（どちらが強いか）と距離（どのくらい先か）を、データの形そのままで見せる。
4. 実データのない数字・プロフィール・機能は出さない。まだないものは「準備中」と書く。値の算出方法は画面に書かない。

### 1-2 色の役割

| 色 | 使う場所 | 使わない場所 |
|---|---|---|
| 紫（塗り）`#6D28D9` violet-700 | 選択中・主ボタンだけ（モード切替の投稿、スイッチ ON、主ボタン、「向きセンサーを開始」） | 飾り・見出し |
| 淡い紫 `#C4B5FD` violet-300 / `#DDD6FE` violet-200 | 枠・フォーカス・アイコンの差し色・地図の線（距離リング、タップ地点の線、対象範囲の外周） | 広い面の塗り |
| 青（sky） | 航空写真などレイヤーの状態と外部リンク（Street View）だけ | それ以外 |
| 赤 `#F87171` red-400 / `#EF4444` red-500 | エラーと **北（N）** だけ | 強調・装飾 |
| 黄（amber） | 注意書き、**コンパスの精度低下** | — |
| ポテンシャルの色ランプ | 地図・コンパス・凡例 | UI 部品 |

紫はネオンにしない。光らせる（glow）のは、**コンパスの最強方向の印**、**文字盤のタップ地点の印**、現在地のドットだけ。

### 1-3 文字の濃さ

基本は 2 段: **主 `#FFFFFF` 90%** と **補助 `#FFFFFF` 50%**。ほかに 100%（選択中、紫の面の上）、95%（投稿カードのキャプション）、92%（文字盤の E/S/W）、85%（小見出し、Range の数字）、80%（アイコンボタン）、60–65%（ラベル）、40–45%（注記・出典・プレースホルダー）、30–35%（最も弱い注記）を使います。

### 1-4 余白・位置

- 画面端の余白は **16px**。
- 上の帯（ミニコンパス・検索バー・モード切替）は **y = 48 を縦の中心**にそろえる（上 16 + ミニコンパス 64 の半分）。部品の間は 8px。
- 角丸は「内側 = 外側 − 余白」の同心円にする（投稿カード 外 16 − 余白 8 = 写真 8、表示モードのサムネイル 外 20 − 枠 3 = 17）。

### 1-5 タッチ領域・入力

- 押せるものは **44 × 44 以上**。見た目が小さい部品（「?」20px、ハート 32px）も押せる範囲は 44px。
- 入力欄の文字は **16px**（iOS がフォーカス時に拡大しないため）。

### 1-6 角丸

| 値 | 用途 |
|---|---|
| full | 地図に浮かぶ小さな部品（ボタン列・モード切替・検索バー・ミニコンパス）、ピル型ボタン、通知、コンパスの ＋/− |
| 28px | 大きな面（**コンパスのカード**、表示モード画面、メニュー、下部シート） |
| 24px | メニュー内のカード |
| 20px | 表示モードのサムネイルの選択枠 |
| 16px | ポップオーバー（検索結果、投稿フォーム）、地図上のポップアップ、面の中の小カード、主ボタン |
| 12px | 行・入力欄・小ボタン |
| 8px | 投稿写真、投稿一覧のサムネイル |

### 1-7 動き

入るときだけ動かし、消えるときはすぐ消す。曲線はすべて `cubic-bezier(0.22, 1, 0.36, 1)`（Figma の Custom bezier に同じ値）。`prefers-reduced-motion` では動かさない。

| 名前 | 時間 | 動き | 使う場所 |
|---|---|---|---|
| ui-pop | 220ms | 97% → 100% に拡大 + 不透明度 0→1 | **コンパスのカード（起点は左上 = ミニコンパスのある角）**、表示モード画面、メニュー |
| ui-drop | 180ms | 上 4px から + 不透明度 | 上の帯の部品、検索結果、通知、スコアの内訳 |
| ui-rise | 260ms | 下 8px から + 不透明度 | 投稿ボタン |
| ui-view | 240ms | 右 12px から + 不透明度 | メニューのページ切り替え |
| sheet-rise | 420ms | 下から持ち上がる | 投稿モードの下部シート |
| モード切替の背景 | 300ms | 選択中の円が左右に滑る | `MapModeToggle` |
| 地図の移動 | 600ms | 距離リングが収まる位置へ | コンパスを開いた・Range を変えた |
| 投稿カード | 180ms（写真 200ms） | 下 8px（写真 6px）から | 地図上の投稿カード |

### 1-8 数字・文言

- 数字（距離、%、件数、値、角度）は等幅数字（OpenType「Tabular figures」）。
- 距離の書き方は 2 通りある: ミニコンパスの中央は **「1km」「200m」（空白なし）**、コンパスモード・地図の距離ラベルは **「1 km」「200 m」（空白あり）**。
- 方角は 8 方位の漢字（北・北東・東・南東・南・南西・西・北西）+ 整数の度。
- 文言は平易な日本語。英字の見出しは `POSTS` / `LATEST POSTS` / `TOKYO NIGHTVIEW`、方位文字 `N E S W` だけ。

## 4. コンパスの全体像

コンパスは画面の 3 か所に出ます。どれも **同じ地点・同じ Range・同じデータ** を見せます。

| 場所 | 部品 | いつ出るか |
|---|---|---|
| 左上 | **ミニコンパス** `MiniCompass`（64px） | コンパスモード以外はいつも（探索・投稿の両方） |
| 地図の上のカード | **コンパスモード** `CompassMode` | ミニコンパスを押す / スマホを横にする |
| 地図そのもの | **距離リング**（`useRangeRings`）、**タップ地点**（`useCompassTarget`）、**現在地の向きのビーム**（`UserLocationMarker`） | 距離リングとタップ地点はコンパスモード中だけ。ビームは向きセンサー動作中ずっと |

### 4-1 中心の地点

- 通常は **現在地**。コンパスモードを開くと現在地の取得を始める。
- デバッグモードで地図をタップして紫のピン（選択地点）を立てたときは、その地点。ピンを立て直すと、タップ地点の印は消える。

### 4-2 Range

- 50 m / 100 m / 200 m / 500 m / 1 km / 5 km / 10 km の 7 段階。**初期 1 km**。
- コンパスモードの ＋（狭める）/ −（広げる）で変える。ミニコンパスの中央の文字も同じ値になる。
- Range を変えると、タップ地点の印は消え、地図は外側の距離リングが収まる位置へ 600ms で動く。

### 4-3 開く・閉じる

```
ミニコンパスを押す ─┬─ 向きセンサーを開始（止まっていれば）
                    ├─ 現在地の取得を開始（選択地点がなければ）
                    └─ コンパスモードを開く（カードが左上から ui-pop）

スマホを横にする ──── コンパスモードを開く（センサーは自動で開始しない）
縦に戻す ─────────── 横にして自動で開いた場合だけ閉じる

× を押す ─────────── 閉じる。タップ地点の印は消える。向きセンサーは止めない
```

コンパスモード中は、ミニコンパス・検索バー・モード切替・投稿シート・投稿ボタンを隠し、右下のボタン列（2 段）だけ残します。

## 5. コンパスの形が決まる仕組み（データ → 見た目）

コンパスの弧・目盛り・ヒートマップの形は、固定のデザインではなく、地点のデータから毎回計算されます。Figma で「それらしい例」を作るときは、この手順で形を決めると実物と同じ性格の絵になります。

### 5-1 サンプリング

- 中心から **24 方位**（15° ごと、0° = 北、時計回り）× 距離（0, 25, 50, 100, 200, 350, 500, 750, 1000, 1500, 2000, 3000, 4000, 5000, 6500, 8000, 10000 m）の点でタイルの色を読み、値（raw）に戻す。
- 読む距離は Range まで（1 km 以下の Range は常に 1 km まで読んでおく）。

| Range | 使う距離 |
|---|---|
| 50 m | 0, 25, 50 |
| 100 m | 0, 25, 50, 100 |
| 200 m | 0〜200（5 点） |
| 500 m | 0〜500（7 点） |
| 1 km | 0〜1000（9 点） |
| 5 km | 0〜5000（14 点） |
| 10 km | 0〜10000（17 点） |

### 5-2 強度 s（見た目の強さ）

```
raw < 0.006 のとき   s = 0
それ以外             s = ( (raw − 0.006) / (0.1635 − 0.006) ) ^ 0.55   （0〜1 に切る）
```

| raw | 0.006 | 0.01 | 0.014 | 0.02 | 0.03 | 0.048 | 0.08 | 0.12 | 0.1635 以上 |
|---|---|---|---|---|---|---|---|---|---|
| s | 0 | 0.13 | 0.19 | 0.26 | 0.36 | 0.48 | 0.66 | 0.84 | 1 |

0.55 乗なので、弱い値も見えやすく持ち上がります。0.1635 以上は同じ見た目になります。

### 5-3 3 種類の「方向ごとの強さ」

| 名前 | 計算 | 使う部品 |
|---|---|---|
| **方向プロファイル** | 方位ごとに、距離 0〜Range の中の最大の raw → s。**中心（距離 0）も含む** | ミニコンパスの弧 |
| **外側プロファイル** | 方位ごとに、距離 0 より大きく Range 以下の中の最大の s。**中心を除く**（中心が明るい地点で全方向が同じ値になって差が消えるのを防ぐ） | 文字盤の目盛り（棒グラフ） |
| **最強方向** | 方向プロファイルで s が最大の方位（同じ値なら 0° から時計回りに数えて先の方位） | 文字盤のひし形 |

24 方位の値は、**円周方向のガウス重み付き平均（σ = 18°）** で 360 方向（1° ごと）へなめらかにしてから描きます。

### 5-4 ヒートマップのマス目

- 方位 **180 本**（2° ごと）× 距離 **72 段**（Range を 72 等分した各段の中央）。
- 各マスの raw は、24 方位 × サンプル距離の格子から、方位（円周）と距離で双一次補間した値。そこから s を出す。

### 5-5 Figma 用の例データ

実物の地点データではなく、形を作るための**例**です（北東〜東が強く、南西が弱い地点）。Figma のフレームには「例」と書いておいてください。

| 方位 | 0 | 15 | 30 | 45 | 60 | 75 | 90 | 105 | 120 | 135 | 150 | 165 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| s | 0.30 | 0.35 | 0.48 | 0.62 | 0.70 | 0.66 | 0.55 | 0.42 | 0.30 | 0.22 | 0.18 | 0.15 |

| 方位 | 180 | 195 | 210 | 225 | 240 | 255 | 270 | 285 | 300 | 315 | 330 | 345 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| s | 0.12 | 0.10 | 0.10 | 0.14 | 0.20 | 0.26 | 0.30 | 0.28 | 0.24 | 0.22 | 0.24 | 0.27 |

この例では、最強方向は 60°（北東寄り）、目盛りが伸びるのは 30°〜90° あたり、色は 60° 付近が `#DF7923` 前後です。

形を厳密に再現したいときは、実機の画面で React DevTools から `CompassMode` の `data`（`directionProfile`・`samples`・`polarField`）と `heading` を取り出し、この章の式で描きます。スクリーンショットからは逆算できません。

## 6. 回転のルール

N を上にした状態（回転 0）で組み、実際の画面では下の表のとおり回ります。Figma では回転 0 の版と、例として「向いている方角 北東 42°」の版（文字盤を −42° 回したもの）を作るとよいです。

| 部品 | 回る量 | 何に合わせるか |
|---|---|---|
| ミニコンパスのリング・目盛り | −rotation | rotation = センサー動作中は **端末の向き**、それ以外は **地図の回転（bearing）**。つまり N の目盛りは常に画面上の本当の北を指す |
| ミニコンパスの前方の扇形 | 回らない（画面の上に固定） | 端末が向いている方向 = 画面の上 |
| ミニコンパスの Range の文字 | 回らない | — |
| 文字盤の目盛り（SVG 全体） | −heading | **端末の向き。センサーが止まっているときは 0（北が上）で、地図の回転には合わせない** |
| 文字盤の N/E/S/W | 目盛りと一緒に位置が回り、文字だけ +heading 戻して**常に正立** | — |
| ヒートマップ | −heading | 同上 |
| 前方の扇形（文字盤） | 回らない | 画面の上 |
| 最強方向のひし形 | 最強方位 − heading | — |
| タップ地点の印 | タップした方位 − heading | — |
| 地図の現在地のビーム | 端末の向き − 地図の回転 | 地図の上で本当の向きを指す |

端末の向きは、センサーの値を毎フレーム 18% ずつ追いかけてなめらかにし、1° 未満の揺れは無視しています（Figma の遷移で見せるなら 300ms 前後のゆっくりした回転）。

方位文字・中心マーカーは描きません（中央に Range を置くため）。

**色付きの弧の描き方**

1. 方向プロファイル（5-3）を 360 方向へなめらかにする。
2. 円を **2° ごとの 180 個の扇形** に分ける。扇形 i（開始角 a = 2i）の強度 s は、なめらかにした値の a + 1°。
3. s ≤ 0.02 の扇形は描かない（基礎リングだけが見える）。
4. 各扇形: 内半径 104、外半径 `122 + 10s`、開始 a 〜 終了 `a + 2.6°`（隣と 0.6° 重ねて隙間を消す）。塗り = 色ランプ(s)、不透明度 `0.25 + 0.75s`。
5. **発光**（s ≥ 0.35）: 同じ扇形を不透明度 5% で塗り、影（色ランプ(s)、不透明度 `8 + 32s` %）を付ける。ぼかしは表示上 **約 0.9〜2.6px**（Canvas の shadowBlur `8 + 16s` は拡大縮小の影響を受けないため、DPR 2 以上の端末では表示上この大きさ）。Figma では発光用の扇形を背面に複製し、Layer blur 1〜3px で近似。
6. **外周のハイライト**（s ≥ 0.5）: 外半径の上に円弧、太さ 3（表示 0.64px）、色 = 色ランプ(min(1, s + 0.15))、不透明度 `60s` %。

Figma では 180 個の扇形を手で作る必要はありません。強度が近い範囲をまとめて、Arc（Ellipse の Arc + Ratio）で 10〜20 個程度の扇形に分けると十分に近い見た目になります。角度 0° が上（北）、時計回りです（Figma の Arc の開始角は右が 0° なので、−90° ずらして入れる）。

**強い方向の決め方（棒グラフ）**

1. 外側プロファイル（5-3）を 360 方向へなめらかにし、各目盛りの方位の値 s を取る。
2. 全方位の最大 max・最小 min を取る。`max − min ≤ 0.03` なら、どの目盛りも強調しない（全方向が同じくらいの場所）。
3. 相対値 `r = (s − min) / (max − min)`。強調 `emphasis = max(0, (r − 0.5) / 0.5) ^ 1.5`。→ **上位半分の方向だけ**伸び、いちばん強い方向で最大。
4. 長さ = 基本の長さ + 9 × emphasis、色は上の表。色は相対値ではなく **s そのもの**で決まる（全体が弱い場所では、伸びても暗い紫）。

例データ（5-5）では、30°・45°・60°・75°・90° あたりの目盛りがオレンジ〜赤で伸び、60° が最長（+9）になります。

### 9-3 円盤とヒートマップ

|---|---|---|

- **マス目**: 方位 180 × 距離 72（5-4）。マス = 内半径 `14 + 1.5d` 〜 外半径 `14 + 1.5(d+1) + 0.4`、方位 ±1° + 0.3°（重ねて隙間を消す）。塗り = 色ランプ(s)、不透明度 `0.12 + 0.78s`。s = 0 でも 12% の暗い紫が乗る。

**見え方の特徴（ここが一番ずれやすい）**

- **全体はほぼ黒**。s = 0 のマスは `#14121E` を 12% で重ねるだけなので、地の `#080B10` とほとんど区別がつかない。紫として見えてくるのは s が 0.2 を超えたあたりから。ふつうの地点では、円盤の大部分は暗く、明るい場所だけがぼんやりした「にじみ（雲）」として浮かぶ。
- **境目がない**。マス目は方位 2°・距離 Range/72 と細かく、値は補間され、さらにぼかしが掛かるので、扇形の角や同心円の帯は見えない。見える線は、白 14% の距離ガイドの円 3 本と円盤の枠だけ。
- **色の付く範囲は半径 122 まで**。その外側（122〜150）はマス目がなく、地の `#080B10` のまま。外側の円（Range）と円盤の枠のあいだは、**内側と同じ暗さの帯**で、明るい灰色にはしない。

**Figma での作り方**

1. 円盤の中（177.5 の円、`#080B10`）を作る。
2. 明るい場所ごとに、楕円や扇形を 1 つずつ置く（色ランプの色、不透明度は 2-4 の「ヒートマップ」の列）。形は方位方向に長い・距離方向に長いなど、データに合わせる。
3. それぞれに **Layer blur 6〜12px** を掛けて、境目を消す。強い場所は、中心に小さく明るい色、外側に大きく暗い色の 2 枚重ねにすると、実物のにじみ方に近づく。
4. 全体を半径 72.2 の円でマスクする（Range の外へにじみ出さない）。
5. 上に距離ガイドの円 3 本（白 14%、0.6px）と中心のマーカーを置く。

扇形を並べて塗り分ける方法（ブロック状・帯状になる）は使わないでください。実物と一番違って見えます。完全に合わせたいときは、例データから実際の描画コードで PNG を書き出して貼るのが確実です。

**空の状態**（データがない）: 円盤の中央に、左右 24 の余白で 11px・行高 1.625・白 45%・中央揃え。読み込み中「夜景ポテンシャルを読み込んでいます…」、地点がない・データがない「選択地点または現在地のデータがありません」。目盛り・前方の扇形は出る（目盛りは強調なし）、ひし形は出ない。
